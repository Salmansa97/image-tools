The problem with online image tools

Almost every free image tool on the web works the same way: you upload your picture to a server, something happens to it there, and you download the result. That model asks you to trust an organisation you know nothing about with a file you may care a great deal about — a passport scan, a medical document, a photograph of your children, a screenshot of something confidential from work.

Most of those sites publish a privacy policy promising that files are deleted after an hour. You have no way to verify it. The file was still transmitted across the internet, still written to a disk you do not control, and still handled by code you cannot inspect.

A different approach

Modern browsers already contain everything needed to decode, transform and re-encode an image. The same engine that displays a JPEG on a web page can read it into a canvas, resize it, and write a new file back out — all in memory, on your own machine.

ImageTools is built entirely on those capabilities. When you add a picture, it is read directly from your disk into your browser's memory. The processing runs in Web Workers, which are background threads, so even a large batch does not freeze the page. The result comes back as a file your browser offers you to save. At no point does any image data touch a network connection.

You do not have to take our word for it. Open your browser's developer tools, switch to the network tab, and process an image. You will see no upload. Better still, load the page and then disconnect from the internet entirely — every tool keeps working.

How it is built

The site is an Angular application using standalone components and signals. Pages are prerendered at build time, which means a search engine — or a visitor on a slow connection — receives complete, readable HTML without waiting for JavaScript.

What this approach cannot do

Honesty matters more than marketing, so here are the trade-offs. Processing happens with your device's memory and processor, which means a ten-year-old phone will be slower than a current laptop, and an extremely large batch can exhaust available memory.

We are also limited to formats browsers can both read and write: JPG, PNG and WebP. A server-side tool can offer HEIC, AVIF, TIFF and RAW because it can bundle any library it likes. We cannot — and we would rather tell you that than quietly convert your file into something mislabelled.

Finally, PNG compression is genuinely harder without a dedicated encoder. We reduce the colour palette, which works well for graphics and screenshots, but a specialist tool will beat us on photographic PNGs. For those, converting to WebP will save far more than any PNG optimiser.
